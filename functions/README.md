# ZIVOZONE Cloud Functions — written, not deployed

Full context, rationale, and deploy steps are in `index.js`'s header comment — read that first.

In short: this directory is a complete, ready-to-deploy Cloud Function
(`verifyChallengeResult`) that re-grades a player's actual submitted answers server-side against
`data/answer-key.json`, and only credits the ZIVO reward if the server's own grading agrees it was
really a perfect round. It closes the gap where today's reward is entirely self-attested by the
client.

**Nothing here is deployed.** The project is staying on Firebase's free Spark plan for now, and
Cloud Functions require the Blaze (pay-as-you-go) plan to exist at all. The live site does not call
this function and does not depend on it — `core/modules/runtime/server-verify.js` is a genuine no-op
until `window.ZIVOZONE_CONFIG.CLOUD_FUNCTIONS_ENABLED` is explicitly turned on, which only happens
after this is deployed.

## Files

- `index.js` — the callable function itself (auth, session-timing check, grading, idempotent credit).
- `grading.js` — the pure answer-grading logic, zero Firebase dependency on purpose, so it can be
  unit-tested without an emulator or network access.
- `data/answer-key.json` — generated by `scripts/export_answer_key.js` from the live question bank.
  Regenerate it (`node scripts/export_answer_key.js` from the project root) any time the question
  bank changes, before deploying.
- `test/grading.test.js` — `node test/grading.test.js` (or `npm test`), no install required. Runs
  entirely against the real, current `answer-key.json`.
- `package.json` — `firebase-admin`/`firebase-functions` dependencies for when this is deployed;
  not installed in this project's sandbox (no npm registry access here), so `npm install` must be
  run from wherever this is actually deployed from.

## To deploy later

1. Upgrade the Firebase project to the Blaze plan.
2. `node scripts/export_answer_key.js` (refresh the answer key if the question bank changed).
3. `cd functions && npm install`
4. `firebase deploy --only functions`
5. Set `window.ZIVOZONE_CONFIG.CLOUD_FUNCTIONS_ENABLED = true` in `index.html`, then re-run
   `scripts/release.py` so every generated page picks it up.

See `firestore.rules`' "FUTURE TIGHTENING, INERT, NOT ACTIVE" comment block near the end of the file
for what could be tightened afterward, once this path is deployed and proven reliable.
